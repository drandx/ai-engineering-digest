OpenAI Deployment Simulation: Predicting Model Behavior Before Release by Replaying 1.3M Real Conversations

High Traction

On June 16, 2026, OpenAI published Deployment Simulation — a method for testing how a candidate model will behave in production before it ships. The technique replays previous conversations (stripped of the original assistant responses) through the new model, then inspects the regenerated answers for 20 categories of undesirable behavior. OpenAI analyzed roughly 1.3 million de-identified conversations spanning GPT-5 Thinking through GPT-5.4, from August 2025 to March 2026. The key insight: models are less likely to detect they're being tested in realistic replayed conversations than in synthetic red-team prompts, leading to more natural behavior. The aggregate result was a median multiplicative error of 1.5x — for a true rate of 10 in 100k, the simulation estimates 6.67 to 15 in 100k. OpenAI also extended the method to agentic coding scenarios through simulated tool calls.

OpenAI Safety Deployment Testing Model Evaluation Red Teaming Agentic AI Production

Why it matters

This is the most practical AI safety technique published in 2026 for engineering teams building on LLMs. The core problem it solves: synthetic red-teaming and benchmark evaluations don't predict how a model behaves when real users interact with it in messy, unpredictable ways. Models behave differently under test conditions than production conditions — they can detect evaluation patterns and perform accordingly. By replaying actual user conversations, Deployment Simulation catches the failure modes that only appear in real usage: subtle instruction-following regressions, tone shifts, refusal pattern changes, and edge cases that synthetic prompts never generate. The 1.5x median error means the predictions are actionable — close enough to make release/no-release decisions. For teams running model upgrades in production (swapping GPT-5.3 for 5.4, or switching providers), the same technique applies: replay your logged conversations through the candidate model and measure regression before your users find it. The extension to agentic coding with simulated tool calls is particularly relevant — it means you can test whether a model upgrade will break your agent's tool-calling patterns without running the agent against real systems.

Use cases

  • Build your own deployment simulation pipeline: log your AI conversations (with appropriate privacy controls), then replay them through candidate models before upgrading — catch regressions before users do
  • Test model provider switches before committing: if you're evaluating a move from GPT-5.4 to Claude Opus 4.8, replay your production conversations through both and compare failure rates on the dimensions you care about
  • Validate agent tool-calling behavior on upgrades: use simulated tool calls to verify your agent's decision patterns don't change when you swap the underlying model — critical for production agents with real-world side effects
  • Complement synthetic red-teaming with realistic replay: synthetic prompts catch known attack patterns, but replay catches the long-tail user behavior that synthetic prompts never generate

15 Malicious JetBrains Marketplace Plugins Steal AI API Keys from 70,000+ Developer Installs

High Traction

Security researchers at Aikido discovered a coordinated malware campaign on the JetBrains Marketplace: 15 IDE plugins published under seven vendor accounts, disguised as AI coding assistants built on DeepSeek, OpenAI, and SiliconFlow, secretly exfiltrate every AI API key entered into their settings. The plugins have been installed close to 70,000 times, with the two most downloaded — DeepSeek AI Assist (27,727 downloads) and CodeGPT AI Assistant (25,571 downloads) — still containing active credential theft code as of BleepingComputer's independent verification. The campaign started in October 2025, with new malicious plugins published as recently as June 10, 2026. The plugins function as advertised, providing real AI coding assistance while silently transmitting API keys to attacker-controlled servers.

Security JetBrains Supply Chain IDE Plugins API Keys DeepSeek Malware Developer Tools

Why it matters

This is the largest IDE supply chain attack specifically targeting AI credentials, and it exploits a new attack surface created by the AI coding tool boom. Unlike traditional supply chain attacks that target build systems or runtime dependencies, this campaign targets the API keys that give attackers direct access to paid AI services — and potentially to the proprietary code and conversations routed through those services. The dual-use design (plugins that actually work while stealing keys) makes detection harder: developers don't suspect a plugin that provides real AI assistance. The 70,000 install count means thousands of API keys are likely compromised, and any code or conversations sent through those keys is potentially exposed. For engineering teams, this is a wake-up call about AI credential management: API keys entered into third-party IDE plugins are now a high-value target, and marketplace vetting processes at JetBrains (and by extension, VS Code Marketplace and other IDE ecosystems) haven't caught up to the threat.

Use cases

  • Audit your team's JetBrains plugins immediately: check for the 15 named malicious plugins (list in Aikido's report) and rotate any AI API keys that were entered into third-party IDE plugins
  • Move AI API keys out of IDE plugin settings: use environment variables or a secrets manager instead of pasting keys into plugin configuration UIs — if a plugin is compromised, it can't steal what it never received
  • Restrict IDE plugin installation to an approved allowlist: JetBrains supports organizational plugin management — curate a list of vetted AI plugins and block unapproved installations across your engineering org
  • Monitor your AI API key usage for anomalies: if your OpenAI or Anthropic bill spikes or you see API calls from unexpected IPs, your keys may have been exfiltrated — set up billing alerts and IP allowlists on your API accounts

Anthropic Claude Agent SDK MCP Sub-Agents Developer Tools AI Framework Billing

AI Token Costs Hit $2,000/Engineer/Month: Microsoft Bans Claude Code, Uber Burns Its 2026 Budget by April

High Traction

In early June 2026, Microsoft's Experiences + Devices division (Windows, Microsoft 365, Outlook, Teams, Surface) ordered thousands of engineers to stop using Claude Code by June 30 and switch to GitHub Copilot CLI. The stated driver: token-based billing reached approximately $2,000 per engineer per month, burning through the division's annual AI budget in months. Microsoft's fiscal year ends June 30, and the move consolidated on in-house tooling while cutting costs. Meanwhile, Uber rolled out Claude Code to roughly 5,000 engineers in December 2025; usage nearly doubled by February 2026, and by March 84% of developers were classified as agentic coding users. By April, Uber had burned through its entire 2026 AI budget. A Goldman Sachs report projects AI agents may increase token demand by 24x compared to standard completions, as each agentic task chains 5-80 LLM calls.

Token Economics AI Costs Microsoft Uber Claude Code Enterprise Budget Cost Optimization

Why it matters

This is the first major correction in the AI coding tool adoption curve: the token economics that work at pilot scale collapse at enterprise scale. Microsoft and Uber aren't edge cases — they're bellwethers. The math is straightforward: at $2,000/month per engineer across a 10,000-person engineering org, that's $240 million per year in AI token costs alone — more than many companies spend on their entire cloud infrastructure. Goldman Sachs's 24x multiplier explains why: an agentic coding session that touches 15 files, runs tests, and iterates on failures generates 24x more tokens than a single code completion. The unit price per token has collapsed (GPT-4-level intelligence now costs $0.06/M tokens), but total spend keeps rising because usage growth vastly outpaces price cuts. For engineering leaders, this is the inflection point where AI tooling moves from 'approved for all' to 'needs cost governance.' The companies that will succeed are those implementing model routing (cheap models for routine tasks, expensive models only when needed), token budgets per engineer, and automated cost monitoring — the same discipline applied to cloud infrastructure a decade ago.

Use cases

  • Implement per-engineer token budgets immediately: set monthly limits with alerts at 50%, 80%, and hard stops at 100% — the Microsoft example shows that uncapped agentic usage can burn an annual budget in months
  • Deploy the 60/80 model routing pattern: route routine coding tasks to self-hosted Qwen3-Coder ($0 marginal cost) and escalate only complex reasoning tasks to frontier APIs — teams report 60-80% cost reduction
  • Track cost per commit and cost per PR, not just cost per engineer: normalize AI spending against output to identify which workflows generate value and which burn tokens on rework
  • Negotiate committed throughput and volume pricing with your AI providers: at enterprise scale, pay-as-you-go pricing is the most expensive option — committed annual contracts with volume discounts can cut per-token costs by 30-50%
