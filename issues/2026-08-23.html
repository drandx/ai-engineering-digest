DeepSeek Harness Hits 180K Stars: The Agent Runtime Where Everything Is a Plugin

High Traction

DeepSeek released deepseek-harness on August 13 under MIT license — an agent harness where the model, tool registry, sandbox, session log, web interface, and even the agent loop itself are swappable plugins. It hit 50K stars in 12 hours, 95K in 48 hours, and now sits at 180K+ stars with 19.7K forks, making it one of the fastest-adopted developer tools in GitHub history.

AI DeepSeek Agents Open Source Harness

Why it matters

This isn't just another Claude Code alternative — it's a fundamentally different architecture. By making the agent loop itself a plugin, DeepSeek is proposing that agent runtimes should be reconfigurable without restarts and eventually support agents that modify their own execution. The MIT license and plugin-first design lower the barrier to building custom agent workflows. At 180K stars, it's already the second most-starred agent harness after OpenClaw.

Use cases

  • Building custom agent workflows with swappable components
  • Running different agent loops for different task types
  • Self-hosted agent infrastructure with full control
  • Experimenting with agent architectures without framework lock-in

Traction

Qwen3.8-2.4T: Alibaba's First Qwen-Max-Class Open-Weight Model With Day-0 Inference Support

High Traction

Alibaba released Qwen3.8-2.4T-A95B, a 2.4-trillion-parameter sparse MoE model with 512 experts and 95B active parameters, as an open-weight release. It's built on the Qwen 3.5 architecture with a hybrid backbone mixing full attention (every 4th layer) with linear attention. vLLM, SGLang, and LMSYS Miles all shipped day-0 support. FP4-quantized versions from Inferact run on a single node.

AI LLM Open Source Alibaba Inference

Why it matters

This is the first Qwen-Max-class model available as open weights. The hybrid attention architecture — full attention at every 4th layer, linear attention elsewhere — is a production-relevant design choice that trades quality for throughput in a measurable way. The day-0 support from vLLM and SGLang means you can self-host it today. FP4 quantization fitting on a single node makes this accessible to teams without multi-node GPU clusters.

Use cases

  • Self-hosting a frontier-class MoE model for code and reasoning
  • Running quantized inference on single-node GPU setups
  • Fine-tuning a 2.4T model for domain-specific agent workloads
  • Comparing open-weight frontier models against closed APIs

Traction

  • First Qwen-Max-class open-weight release
  • Day-0 support from vLLM, SGLang, and LMSYS Miles
  • FP4/FP8/BF16 checkpoints available from Inferact
  • HN discussion with community benchmarking
  • Reddit benchmark frenzy comparing to frontier models

Microsoft Open-Sources Orchard: 3B Active-Parameter Agents Hit 69.7% on SWE-bench Verified

High Traction

Microsoft Research released Orchard, an open-source framework for scalable agentic AI built around Orchard Env, a reusable Kubernetes environment service. Orchard-SWE achieves 69.7% on SWE-bench Verified (73.0% with value-model reranking) using only ~3B active parameters — approaching frontier systems using 10x larger models. The framework supports software engineering, web navigation, and personal assistant agents, and can train inside real harnesses like Codex and OpenClaw.

AI Microsoft Research Open Source SWE-bench

Why it matters

A 3B active-parameter model hitting 69.7% on SWE-bench Verified is a remarkable efficiency result — it shows that small, well-trained models can compete with frontier systems on real engineering tasks. The open release of training data, evaluation methods, and the Kubernetes-based environment service addresses the biggest bottleneck in agentic AI research: the inability to reproduce results without proprietary infrastructure.

Use cases

  • Building domain-specific agents with small, efficient models

Arcee AI Ships NAC: An Open-Source Harness That Separates Agent Context From Persistent State

Growing

Arcee AI released NAC (Apache-2.0), an agent harness designed for long-running engineering work that separates temporary execution context from persistent workstream state. Instead of accumulating everything in one transcript — where context rot degrades model performance — NAC coordinates parallel agent workers with independent contexts while maintaining shared persistent state across sessions that can span hours or days.

AI Agents Open Source Harness Context Management

Why it matters

Context rot is a proven failure mode for long agent sessions: model performance degrades as irrelevant context accumulates. NAC's architectural separation of 'context needed to perform an action' from 'state needed to continue a workstream' is a principled response. If you've hit the wall where agent sessions become unreliable past 30 minutes, NAC's approach of parallel workers with independent contexts is worth evaluating.

Use cases

  • Long-running engineering tasks that span hours or days
  • Multi-step agent workflows where context rot causes failures
  • Parallel agent coordination on complex implementation tasks
  • Persistent workstreams that survive session boundaries

Traction

  • From Arcee AI, a well-known open-weight model company
  • Apache-2.0 license
  • Addresses context rot — a documented failure mode
  • Sessions demonstrated spanning hours to days
  • Parallel worker architecture with shared persistent state

JetBrains Rider Gives AI Agents Access to Its Refactoring Engine: 83% Faster, 64% Cheaper

High Traction

JetBrains shipped a bundled 'refactoring-code' skill in Rider 2026.2.1 that gives AI agents direct access to the IDE's structural refactoring engine. In benchmarks across 15 C# refactoring tasks, agents with the skill were 83% faster (157.9s → 26.6s median), 64% cheaper ($0.52 → $0.19 per task), and used 63% fewer tool calls (17 → 6.2). Without it, agents were calling sed 392 times and git 422 times to approximate refactorings that the IDE does structurally.

DevTools JetBrains Rider Refactoring Agents

Why it matters

This is the first major IDE to expose its refactoring engine as a tool agents can call directly. The numbers are striking: agents without IDE refactoring were calling dotnet build 163 times just to check if their text edits were correct — using the compiler as an oracle. Rider's resolved syntax tree eliminates the guess-and-check loop entirely. This pattern — IDE-as-tool-server for agents — will likely spread to every major IDE.

Use cases

  • Agent-driven C# refactoring with structural correctness guarantees
  • Reducing agent token costs on refactoring-heavy tasks
  • Eliminating guess-and-check loops in agent code modifications
  • Extending the IDE-as-tool-server pattern to other languages

Traction

  • 83% faster, 64% cheaper, 63% fewer tool calls in benchmarks
  • Bundled in Rider 2026.2.1 (ships by default, nothing to enable)
  • Powered by ReSharper's structural refactoring engine
  • First major IDE to expose refactoring as an agent-callable skill

fx by Vercel Labs: A 7.8MiB Zig Coding Agent With 10µs Cold Starts

Growing

Vercel Labs open-sourced fx (Apache-2.0), a native coding agent written in Zig that ships as a single 7.8MiB binary with 10-microsecond cold starts and single-digit megabytes of memory. Originally an internal Vercel tool, it's designed as an embeddable harness for CI pipelines, agent sandboxes, and resource-constrained environments. It includes a WebAssembly SDK, Agent Client Protocol support, and MCP integration.

DevTools Vercel Zig Agents Performance

Why it matters

Claude Code burns ~33K tokens on startup and carries a full Node runtime. fx bets on the opposite extreme: a coding agent that's small enough to pack hundreds of instances per machine. The Zig binary approach means no runtime dependencies. If you're running agents in CI, sandboxes, or anywhere density matters, this is the SQLite of coding agents. The catch: inference currently routes through Vercel AI Gateway, though more providers are promised.

Use cases

  • High-density agent deployments in CI/CD pipelines
  • Embedding a coding agent in resource-constrained sandboxes
  • Running hundreds of agent instances on a single machine
  • Lightweight agent harness with no Node/Python runtime

ZenML Rebuilds Kitaru: Turn Production Agent Traces Into Repeatable Test Suites

Growing

ZenML rebuilt Kitaru around a single premise: production is already generating your best test cases. The new Kitaru provides a structured pipeline to capture agent traces from production, attach expert judgments, turn them into replayable scenarios with tool-call sandboxing (so replays don't send real emails or issue refunds), and run the same cases against every future change. It replaces the ad-hoc spreadsheet-and-script approach most teams use today.

Infrastructure ZenML Testing Agents MLOps

Why it matters

Every team running agents in production hits the same eval problem: traces live in one tool, expert judgments in another, regression cases are collected manually, and replays are custom scripts. Kitaru provides the structured path from 'this went wrong in production' to 'this is now a repeatable test we run against every change.' The tool-call sandboxing for replays solves the real blocker — you can't replay an agent session that issues refunds in production.

Use cases

  • Building regression test suites from production agent failures
  • Safe replay of agent sessions with side-effect sandboxing
  • Structured expert evaluation of agent behavior
  • Continuous evaluation against every model or prompt change

Traction

  • From ZenML, established MLOps platform
  • Published August 18, 2026
  • Addresses a universal pain point for production agent teams
  • Includes tool-call sandboxing for safe replay
  • Structured pipeline from traces to evaluators

Infrastructure Pulumi Terraform IaC DevOps

The agentic angle is real: agents working with typed Python/TypeScript/Go code can leverage IDE tooling, type checking, and refactoring — capabilities that are limited with HCL. This positions Pulumi as the IaC layer most compatible with the agent-driven infrastructure management wave.
