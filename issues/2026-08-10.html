NVIDIA Open-Sources NOOA: An Object-Oriented Python Framework That Turns an AI Agent Into a Single Class

Emerging

NVIDIA Labs released NOOA (Object-Oriented Agents), a model-agnostic Python framework where methods are agent actions, fields are state, docstrings are prompts, and type annotations are runtime-enforced contracts. Methods with an ellipsis body are completed by an LLM loop; normal methods stay deterministic.

AI Agents Python NVIDIA

Why it matters

Scores 82.2% on SWE-bench Verified and 85.1% on ARC-AGI-3 at roughly half the tokens of competing open harnesses. If you're building internal agents, this collapses prompt templates, tool schemas, and workflow graphs into testable, version-controlled Python — no new DSL required.

Use cases

  • Build internal coding agents with standard Python tooling
  • Repository issue triage and automated patching
  • Terminal and infrastructure automation
  • Vulnerability validation pipelines

Traction

  • Apache 2.0 on GitHub under NVIDIA-NeMo/labs-OO-Agents
  • Published benchmarks: 82.2% SWE-bench Verified, 86.8% CyberGym L1, 85.1% ARC-AGI-3
  • PyPI v0.0.8 released July 30, 2026
  • Covered by MarkTechPost and multiple AI newsletters

NVIDIA Releases NemotronLabs VoiceChat 11B: First Open Full-Duplex Speech Model With Live Tool Calling

Emerging

An open 11B end-to-end speech-to-speech model that listens while it speaks, handles barge-in at 480ms, and calls tools via a separate output channel — all without chaining ASR + LLM + TTS.

AI Voice Speech NVIDIA

Why it matters

Eliminates the multi-model orchestration stack for voice agents. Engineers building voice interfaces get 450ms smooth turn-taking and live tool calling in a single model, with permissive weights on HuggingFace. Still research-preview quality, but it's the first open model to solve full-duplex with tool use.

Use cases

  • Voice agents that handle barge-in naturally
  • Voice front-ends for internal APIs (weather, pricing, order status)
  • Contact center and IVR modernization prototypes
  • Accessibility tooling for hands-free workflows

Traction

  • Weights publicly available on HuggingFace (nvidia/NVIDIA-NemotronLabs-VoiceChat-11B)
  • Benchmarked on Full-Duplex-Bench 1.0 with published metrics
  • Covered by MarkTechPost, HN discussion

LangChain Ships Managed Deep Agents in Public Beta: One Command From Prototype to Production

Growing

Managed Deep Agents lets you author an agent in Python or TypeScript, test it locally in LangSmith Studio, and deploy to a managed runtime with `mda deploy`. LangSmith handles persistence, memory, sandbox lifecycle, and scaling.

Agents LangChain DevTools

Why it matters

The gap between 'demo agent' and 'production agent' is mostly infrastructure: durable execution, memory mounts, sandboxing, human-in-the-loop approvals. This packages all of that behind a single deploy command while keeping agent logic (prompts, tools, middleware) in your control.

Use cases

  • Ship internal research or support agents without building infra
  • Add human approval gates to sensitive agent actions
  • Deploy long-running agents with durable execution guarantees

Traction

  • Public beta launched with Python and TypeScript SDKs
  • Built on LangSmith platform with existing enterprise customer base
  • Open-source harness (Deep Agents) with managed runtime layer

Warp Ships a Standalone Agent CLI: A Terminal-Muxing Coding Agent That Works Anywhere

Growing

The Warp Agent is now a standalone CLI that runs in any terminal — Ghostty, iTerm, VS Code, Windows Terminal. Built on Warp's terminal infrastructure, it natively muxes agent sessions, drives full-screen terminal apps (sqlite, mysql), and works over SSH without a remote binary.

DevTools CLI Agents

Why it matters

Most CLI coding agents treat the shell as a subprocess. Warp's mux architecture means the agent operates inside real terminal sessions — it can switch directories, drive interactive TUIs, and SSH into remote machines. For engineers who live in the terminal, this removes the 'agent can't do that' friction.

Use cases

  • Terminal-heavy development workflows across SSH sessions
  • Drive interactive CLI tools (databases, REPLs) via agent
  • Multi-agent orchestration from the command line

Traction

  • Ships with built-in model routing across frontier and open-weight models
  • Supports multi-agent orchestration and cloud agents
  • Builds on Warp Terminal's existing user base

Blockstor Open-Sourced: A Go Rewrite of LINSTOR for Kubernetes Block Storage, Backed by CNCF Sandbox

Emerging

The Cozystack team open-sourced Blockstor, a from-scratch Go implementation of LINSTOR's REST API for Kubernetes block storage. It uses CRDs and controller-runtime reconcilers instead of LINSTOR's request-based polling model, with LVM/ZFS backends and DRBD replication.

Kubernetes Storage CNCF Go

Why it matters

Existing LINSTOR client tooling (CLI, CSI driver, Piraeus operator) works unchanged — Blockstor is a drop-in backend replacement. The Kubernetes-native reconciler model means no external database, no in-memory state to lose on restart, and better failure recovery. Part of the CNCF Sandbox via Cozystack.

Use cases

  • Replace LINSTOR controller with a Kubernetes-native alternative
  • Block storage for stateful workloads on K8s with DRBD replication
  • GPU cluster storage where LINSTOR scaling limits are a concern

Traction

  • Apache 2.0 under the Cozystack organization
  • CNCF Sandbox project (Cozystack)
  • LINSTOR API compatibility means existing tooling works without changes
  • Covered by Cozystack blog with detailed architecture comparison
