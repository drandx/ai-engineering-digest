Liquid AI Ships LFM2.5-2.6B: An On-Device Agentic Model With 128K Context and Tool Calling

High Traction

Liquid AI released LFM2.5-2.6B, a 2.69B parameter agentic model that runs entirely on-device. It has a 128K context window, native tool calling, and was pre-trained on ~34 trillion tokens. Two checkpoints shipped: a base model for fine-tuning and a post-trained model for agentic workloads. It decodes at 220 tokens/s on an M5 Max in under 2.5 GB of memory.

AI On-Device Liquid AI Open Source Agents

Why it matters

On-device agentic models change the economics and privacy equation for AI-powered tools. At 2.6B parameters with tool calling, LFM2.5 can run agentic workflows on phones, laptops, and edge devices with zero API costs and no data leaving the device. Day-one support in llama.cpp, vLLM, SGLang, and LM Studio means it drops into existing local inference stacks immediately.

Use cases

  • Privacy-preserving on-device agent workflows with zero API costs
  • Edge deployment for automotive, robotics, and IoT agentic tasks
  • Local coding assistants and tool-calling agents on consumer hardware

Traction

  • Open weights on Hugging Face in native, GGUF, MLX, and ONNX formats
  • Day-one support in llama.cpp, vLLM, SGLang, and LM Studio
  • 220 tok/s on M5 Max, single H100 serves ~1.3B tokens/day
  • Tool-use scores competitive with models 4x its size
  • Covered by MarkTechPost on August 6

Microsoft Research Releases Orchard: Open-Source Agentic AI Where 3B Params Hits 69.7% on SWE-bench

High Traction

Microsoft Research released Orchard, an open-source framework for scalable agentic AI research. Built around Orchard Env, a reusable Kubernetes environment service, it supports training and evaluating agents across software engineering, web navigation, and personal assistant domains. Orchard-SWE reaches 69.7% on SWE-bench Verified (73.0% with reranking) using only ~3B active parameters — approaching frontier systems 10x larger.

AI Research Microsoft Open Source SWE-bench

Why it matters

A 3B parameter model hitting 69.7% on SWE-bench Verified challenges the assumption that you need frontier-scale models for effective coding agents. The framework trains agents inside real deployment harnesses (Codex, OpenClaw), not sandboxed toy environments. For teams building custom coding agents, this provides a reproducible training pipeline with open data, open weights, and open evaluation — no proprietary infrastructure required.

Use cases

  • Training custom coding agents on your own data with open infrastructure
  • Evaluating agentic performance across SWE, web, and assistant tasks
  • Building cost-effective coding agents with small open-weight models

First Production-Scale Study of Coding Agents: 3.2M Users, 95 Trillion Tokens From GitHub Copilot

High Traction

Microsoft Research published the first production-scale characterization of agentic coding workloads using sampled GitHub Copilot traces from June 2026: 3.2M users, 13M sessions, 761M LLM calls, and 95T tokens. Key finding: KV cache hit rates average 90% within a turn but drop to 55% across turn boundaries. They built an idle-time predictor that captures 86-90% of total idle time for resource orchestration.

AI Research Infrastructure GitHub Copilot LLM Serving

Why it matters

This paper provides the empirical foundation for building agent-native infrastructure. The finding that KV cache invalidates dramatically at turn boundaries means current LLM serving systems — designed for chatbots — are architecturally mismatched for coding agents. The 1:1 coupling of LLM calls to tool execution and the long-tailed token consumption patterns suggest we need fundamentally different serving infrastructure for agents.

Use cases

  • Designing LLM serving infrastructure optimized for agentic workloads
  • Understanding cache behavior to reduce inference costs for coding agents
  • Building idle-time predictors for GPU resource orchestration

Traction

  • Published by Microsoft Research (arXiv, July 2026)
  • Based on production GitHub Copilot data — 3.2M users
  • First study of its kind at this scale
  • 761M LLM calls and 95T tokens analyzed
  • Quantifies KV cache behavior and idle-time patterns

JetBrains Opens IntelliJ's Java and Kotlin Intelligence Via LSP for VS Code, Cursor, and Agents

High Traction

JetBrains released a preview VS Code extension that brings IntelliJ IDEA's Java and Kotlin language intelligence to VS Code, Cursor, and other LSP-capable editors via the Language Server Protocol. The extension includes smart completion, navigation, code analysis, refactorings, and debugging. Internal trials show the same LSP functionality significantly improves terminal-based agentic workflows like Claude Code and Codex.

DevTools JetBrains LSP Java Kotlin Agents

Why it matters

This is JetBrains acknowledging that developers are splitting time between IDEs and agentic flows. By exposing IntelliJ's battle-tested Java/Kotlin intelligence as an LSP server, coding agents get deterministic language understanding — type-aware navigation, refactoring, and analysis — instead of relying on LLMs to infer code structure. For Java/Kotlin teams, this means their coding agents get the same quality of code intelligence that IntelliJ users have had for years.

Use cases

  • Adding IntelliJ-grade Java/Kotlin intelligence to coding agents
  • Using VS Code or Cursor with enterprise-grade Java language support
  • Improving agentic coding accuracy with deterministic type information

Traction

  • Official JetBrains release (August 2026)
  • Preview extension available for VS Code and forks (Cursor)
  • Internal trials with Claude Code and Codex show 'very promising results'
  • Includes debugging via DAP
  • Supports mixed Java/Kotlin projects

Vercel Ships Agent Plugins 1.0: A Standard Format for Packaging Agent Skills and MCP Servers

Growing

Vercel released Agent Plugins 1.0, an open, vendor-neutral standard for packaging Agent Skills and MCP servers into distributable plugins. A plugin is a directory with a plugin.json manifest and fixed locations for skills and MCP configurations. The format is intentionally minimal — clients handle installation, distribution, and UX. Compatible clients include Claude Code, Cursor, Codex, and others.

DevTools Vercel MCP Agent Skills Standards

Why it matters

Agent Skills and MCP servers are reusable, but every client packages and discovers them differently. Agent Plugins gives extension authors one format instead of adapting the same component for every client. This is the npm-for-agent-tools moment: a shared packaging standard means skills and MCP servers can be distributed, versioned, and discovered across the ecosystem without client-specific rewrites.

Use cases

  • Publishing agent skills that work across multiple coding agents
  • Distributing MCP server configurations as portable plugins
  • Building an ecosystem of reusable agent extensions

Traction

  • Released by Vercel on August 6, 2026
  • 1.0.0 specification publicly available at agent-plugins.org
  • Vendor-neutral — works across Claude Code, Cursor, Codex
  • Builds on existing Agent Skills and MCP standards

Temporal Releases Deputy: Open-Source Supply Chain Security Toolchain Built With AI Agents

Growing

Temporal released Deputy, an open-source, CLI-first security toolchain for inventorying, scanning, triaging, and controlling dependencies across repositories, container images, VM disk images, and SBOMs. It provides a shared, customizable policy layer for local use, CI, and download-time enforcement. Built using Claude Code and Codex, Deputy also puts deterministic supply chain guardrails around AI-assisted development.

Coming from Temporal's security team — who built it for their own estate — it's production-tested, not theoretical.

How Duolingo Built a Production-Ready Agent Platform: Define Once, Run Everywhere

High Traction

Duolingo published a detailed engineering blog on how they built a shared agent platform to stop teams from repeatedly rebuilding the same infrastructure. Agents are defined in a registry (system prompt, MCP servers, repo access), and the platform handles execution, orchestration, observability, and evaluation. Agents are invokable across Slack, internal sites, CLI, and Temporal workflows without rebuilding per surface.

Infrastructure Agents Duolingo Platform Engineering Temporal

Why it matters

Every company deploying AI agents hits the same wall Duolingo did: prototyping is easy, productionizing is the problem. Their solution — a registry-based platform with shared execution, multi-surface distribution, and built-in observability — is the blueprint for how mid-to-large engineering orgs should operationalize agents. The explicit separation of agent definition from infrastructure is the key architectural decision.

Use cases

  • Building a shared agent platform for engineering organizations
  • Registry-based agent definitions with multi-surface distribution
  • Adding observability and evaluation to production agent deployments

Traction

  • Published by Duolingo Engineering on August 4, 2026
  • Addresses the 'agent sprawl' problem multiple companies have flagged
  • Uses Temporal for orchestration — production-proven stack
  • Multi-surface distribution: Slack, CLI, web, workflows
  • Built-in evaluation and observability for all agents
