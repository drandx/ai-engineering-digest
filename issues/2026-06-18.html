Gemini CLI Stops Working TODAY: The 15-Minute Migration to Antigravity CLI (Four Breaking Changes)

High Traction

On June 18, 2026 — today — Google's Gemini CLI stops serving all requests for free, Pro, and Ultra tier users and individual Gemini Code Assist subscribers. No grace period. Any script or CI/CD pipeline calling the `gemini` command fails immediately. Migration to Antigravity CLI (`agy`) involves four breaking changes beyond the binary rename: (1) env var rename from GEMINI_API_KEY to AV_API_KEY, (2) default model changes to gemini-3-pro, (3) `--stream` now emits SSE by default, (4) exit codes are non-zero on tool-use failures. Agent state directory moves from `~/.gemini/` to `~/.antigravity/`. Organizations on Gemini Code Assist Standard, Enterprise, or Google Cloud licenses are unaffected.

Gemini CLI Antigravity CLI Google Breaking Change Migration CI/CD DevOps Deprecation

Why it matters

This is an immediate operational issue. Unlike most deprecations with graceful fallbacks, this is a hard cutover — the binary stops working today. CI/CD pipelines that call `gemini` for code review, changelog generation, or documentation will fail silently or with auth errors. The exit code change is the sneakiest trap: `if gemini ...; then` conditionals break because the new non-zero exit on tool-use failure triggers failure branches even when the model response is correct. The env var rename (GEMINI_API_KEY → AV_API_KEY) will cause silent auth failures in any script reading the old variable. The migration itself is fast (15 minutes for simple setups) but the four breaking changes require explicit fixes — it's not a drop-in rename.

Use cases

  • Audit every `gemini` call in CI/CD pipelines immediately: search GitHub Actions, GitLab CI, Jenkins, and shell scripts — each one breaks today without warning; prioritize pipelines that block deployments
  • Fix the four breaking changes in order: rename GEMINI_API_KEY → AV_API_KEY in all secrets managers, update model flags for the new default (gemini-3-pro), update `--stream` consumers to parse SSE, and fix exit-code conditionals for non-zero tool-use failures
  • Migrate local dev first, then CI: run `npm install -g @google/antigravity-cli` then `agy auth login` — verify interactive queries work before testing tool-invocation workflows in CI
  • Manually migrate persisted state from `~/.gemini/` to `~/.antigravity/`: conversation history and tool configurations saved in sessions are not auto-migrated

144 Mastra npm Packages Backdoored in 88-Minute Attack: North Korean APT Deploys Crypto-Stealing RAT via easy-day-js Typosquat

High Traction

On June 17, 2026, attackers compromised the @mastra npm scope — a popular AI framework with 1.1 million combined weekly downloads — by hijacking the 'ehindero' account, a legitimate former contributor whose scope access was never revoked. In an 88-minute automated campaign (01:12-02:39 UTC), the attacker republished 142 packages with a single injected dependency: 'easy-day-js', a typosquat of the popular dayjs library. The bait version published the day before was clean and fully functional; once the dependency was pinned across @mastra packages with a ^1.11.21 semver range, the attacker could publish a malicious update that npm would automatically resolve. The final payload is a cross-platform information stealer that harvests browser history, extracts data from 160+ cryptocurrency wallet browser extensions, installs persistence on Windows/macOS/Linux, and exfiltrates to a C2 server. Snyk, Orca, and Microsoft Security Blog all link the tradecraft to Sapphire Sleet (BlueNoroff), a North Korean APT known for cryptocurrency theft via developer-targeting supply chain operations. The highest-impact package is @mastra/core with approximately 918K weekly downloads.

Supply Chain Attack npm Mastra Security North Korean APT BlueNoroff Typosquat Cryptocurrency AI Framework

Why it matters

This is the most technically sophisticated npm supply chain attack of 2026 and the first major one targeting AI framework developers specifically. The attack chain is a masterclass in operational tradecraft: the attacker didn't inject malicious code into the packages themselves — they added a clean, functional typosquat as a dependency first, then weaponized it after the dependency was already trusted. The semver pinning (^1.11.21) means any future malicious version matching that range gets pulled automatically on fresh installs. This is worse than a one-time compromise because the attack surface persists as long as the dependency exists. The 88-minute window suggests automation — likely a script that iterated over the @mastra package list and published updated versions in rapid succession. The targeting of AI framework developers is strategic: these developers are more likely to have cryptocurrency wallets (the crypto-AI developer overlap is high) and more likely to have high-value API keys and infrastructure access. The former-contributor-with-stale-access vector is the root cause, and it's endemic across the npm ecosystem — most organizations never audit or revoke scope access when contributors leave. Microsoft publishing a Security Blog post about it within 24 hours underscores the severity.

Use cases

  • Audit your @mastra dependencies immediately: run 'npm ls easy-day-js' in any project using @mastra packages — if it appears in your dependency tree, you were exposed; update to patched versions and rotate any credentials on affected machines
  • Implement contributor access audits as a recurring security practice: the root cause was a former contributor's stale access — audit your npm org, GitHub org, and PyPI project maintainer lists quarterly and revoke access for anyone who is no longer an active contributor
  • Pin exact dependency versions in lockfiles and enable npm audit in CI: semver ranges (^) are the attack surface that made this possible — exact pinning prevents automatic resolution to malicious versions, and npm audit would have flagged the known-malicious easy-day-js within hours of disclosure
  • Add postinstall hook scanning to your CI pipeline: the malicious payload was delivered via a postinstall hook — tools like Socket, Snyk, and StepSecurity's Harden-Runner detect postinstall scripts that download external payloads, which is a strong signal for supply chain attacks

High Traction

Spec Kit, GitHub's open-source toolkit for Spec-Driven Development, has reached 111,000 GitHub stars and 55+ releases since its late February 2026 launch — making it one of the fastest-growing developer tools of the year. The tool provides a CLI and slash commands that structure AI-assisted coding into a repeatable specify-plan-tasks-implement workflow. As of v0.10.0 (June 2026), Spec Kit supports 30+ AI coding agent integrations including Claude Code, GitHub Copilot, Cursor, Gemini CLI, Windsurf, Amp, Codex CLI, Roo Code, Kilo Code, Qwen Code, and OpenCode. The framework imposes a structured workflow where developers write specifications first, the AI generates implementation plans from those specs, the plans are decomposed into discrete tasks, and each task is implemented against the spec — creating an auditable chain from requirement to code.

Spec Kit Spec-Driven Development GitHub Open Source AI Workflow Coding Agents Developer Tools Code Quality

Why it matters

Spec Kit addresses the most common failure mode of AI coding agents: they generate code that is technically correct but doesn't match the developer's intent because the intent was never formally specified. By inserting a specification step before code generation, the workflow creates a contract that both the human and the AI can verify against. This is the 'verification bottleneck' solution the industry has been converging on — as code generation becomes commoditized (any frontier model can write code), the differentiator is whether the generated code actually solves the right problem. The 30+ agent integrations make Spec Kit agent-agnostic, which means teams can adopt the workflow regardless of which coding tool they use. The specify-plan-tasks-implement pattern also creates a natural audit trail: each piece of generated code traces back to a spec, a plan, and a task — useful for code review, compliance, and debugging why the AI made a particular decision. The 111K stars in four months indicate the developer community has been waiting for a structured workflow layer on top of raw AI coding capabilities.

Use cases

  • Add Spec Kit to your existing AI coding workflow as a pre-generation step: write a spec before asking Claude Code or Cursor to implement — the structured requirement reduces rework by giving the AI a verifiable target instead of an ambiguous prompt

The Jevons Paradox of AI Tokens: Prices Down 98% Since 2022, Enterprise AI Budgets Up 6x to $7M — Fortune Reports Consumption Rising 100x

High Traction

Fortune published a June 17 analysis applying the Jevons Paradox to AI token economics: token prices for comparable AI capability have fallen roughly 98% since early 2022 (from $20 per million tokens to ~$0.40), yet average enterprise AI budgets grew from $1.2M/year in 2024 to $7M in 2026. Apollo Global Management's Silicon Data Token Expenditure Index has roughly doubled since late 2025 even as per-token prices cratered. The mechanism is textbook Jevons: lower token prices create more viable use cases, more use cases create more consumption, and consumption growth vastly outpaces price cuts — per-token costs fell 10x while consumption rose 100x. VentureBeat coined the framing 'cheaper tokens, bigger bills' and multiple analysts confirmed that agentic AI is the primary driver: a single agentic task chains 5-80 LLM calls and costs dollars, compared to cents for a one-shot chat query. Deloitte's Tech Trends 2026 report confirms that inference now accounts for approximately two-thirds of all AI compute, and 80% of AI GPU spend is inference-focused.

Jevons Paradox Token Economics AI Costs Enterprise Inference FinOps Cost Optimization Agentic AI GPU Spend

Why it matters

This is the macro-economic framework that explains why every enterprise AI budget story in 2026 follows the same pattern: per-unit costs are falling, total costs are rising, and finance teams are confused. Understanding the Jevons Paradox dynamic changes how you approach AI cost management. Cutting per-token costs (model routing, caching, quantization) is necessary but insufficient — it increases the total addressable use cases, which increases consumption, which can increase total spend. The correct response is not to avoid cost optimization (you should still route and cache), but to pair it with consumption governance: token budgets per team, per-task cost tracking, and automated cost alerts. The agentic AI multiplier is the specific mechanism — a single 'refactor this module' command that spawns 15 sub-agent calls, each with multiple tool invocations, generates 50-100x more tokens than the same question asked as a one-shot chat. This is why Microsoft hit $2,000/engineer/month and Uber burned its annual budget by April. The 80% inference GPU spend number is the infrastructure signal: the industry's compute investment has permanently shifted from training-dominant to inference-dominant, which changes the hardware planning, pricing, and optimization strategies for every team running AI workloads.

Use cases

  • Reframe your AI cost optimization strategy around consumption governance, not just unit cost: model routing and caching reduce per-token costs, but without per-team token budgets and per-task cost tracking, Jevons Paradox means total spend still rises — implement both cost-reduction and consumption-governance simultaneously
  • Track cost per completed task, not cost per token: tokens are the wrong unit for AI ROI — measure what each agentic workflow actually costs end-to-end (all sub-agent calls, retries, tool invocations) and compare against the value of the completed task to identify workflows that burn tokens without completing work
  • Set agentic task budgets with hard stops: configure your coding agents with per-task token limits that kill sessions exceeding a threshold — a runaway agent loop that retries 20 times generates enormous token volume with zero productive output, and without a hard stop there's no natural ceiling
  • Model the consumption growth rate before projecting next quarter's budget: if your team's token consumption grew 40% this quarter despite per-token costs falling 25%, your total spend grew ~5% — project forward from consumption growth, not price trends, to avoid the budget surprise that hit Microsoft and Uber

Why it matters

Both gateways also provide model fallbacks, load balancing, and unified request logging.

AI Gateway Semantic Caching Helicone Portkey LLM Cost Optimization Infrastructure Model Fallback LLMOps Production

Why it matters

The 90% cost reduction from semantic caching is real for the right workloads: if a significant fraction of your queries are near-identical (same user asking the same question differently, CI pipeline running the same code review on similar diffs, documentation generator processing similar files), semantic caching serves the majority of them from cache at zero token cost. The AI gateway pattern also provides production reliability features that go beyond cost: model fallbacks (Claude rate-limits → fall back to GPT-5.5 transparently), canary model deployments (5% traffic to new model version, validate quality before full rollout), and circuit breakers. Not having a gateway in production is the 2026 equivalent of calling external services without retries or circuit breakers — technically functional, operationally fragile.
